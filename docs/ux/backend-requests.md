# Requests to the backend chat

The frontend (ux-redesign) cannot edit the backend. Each line: what, why,
which screen. The backend marks them done in its
`docs/progress/frontend-handoff.md`; this file is then ticked.

- [x] (done by backend; placeholder/hint updated) Order search by the **last digits** of a phone (e.g. 4–9 digits), not only 10+. Why: agents and couriers read the last digits off a waybill or caller ID (audit U-35). Screen: Orders list search, ⌘K.
- [x] (done by backend: booking accepts shipping.manage; the UI never gated it by role) The **Fulfillment** role cannot book a courier: `POST /orders/:id/shipments`, `/orders/bulk` and bulk-ship require `orders.manage`, though the role is meant to book couriers (01 §2.1). Why: the role's main job fails with "no permission". Screen: Orders list bulk "Book courier", order page shipment card. (Permission change → backend decision; frontend will not work around it.)
- [x] `fulfillment` missing from the analytics-hidden roles is a frontend list (`lib/analyticsAccess.ts`) — **fixed in the frontend (S5 commit)**, listed here only so the backend knows the intended rule: Fulfillment has no `analytics.view`.
- [x] (done by backend; the dashboard now sends Accept-Language with every call) Optional `Accept-Language` support: return translated `error.message` (ar/en/fr) for codes the dashboard and storefront do not map. Why: unmapped codes reach the shopper in English (U-02, U-03). Screen: storefront checkout, sign-in. Frontend maps every known code meanwhile.
- [x] (done by backend; queue has the «يتكلم تاني الساعة» picker) Confirmation outcome "postponed" with a **callback time** (`callbackAt`) in the outcome payload. Why: «كلّمني بكرة الساعة ٥» is the most common postponement and is lost today (U-31). Screen: Confirmation queue.
- [x] (done by backend; the list sends dates + the device time zone) Orders list/pipeline/export: a time-zone aware **end** of the date range (accept an ISO `to` as an exact exclusive instant, or a `tz` param). Why: the dashboard now sends `from` as the merchant's local midnight, but `to` is still run to the end of the UTC day, so "until 6 Oct" includes up to 3 hours of 7 Oct in Cairo (audit U-09). Screen: Orders list date range and shortcuts.
- [x] (done by backend; the buy dialog sends a store without a website to set one up, and a bought-but-not-connected domain says so instead of "nothing was charged") **Domain purchase order of checks (money):** a purchase registers the domain at the registrar before checking the store is set up (has a website), so with a real registrar money is spent and the purchase then fails. Check every precondition first. Found while building handoff 176 (Store settings → Domains → Buy a domain).
- [x] (done by backend; the www of a domain bought here shows «جهزناه لك», no record to add) **Root domain purchase and www:** buying a root domain turns on the www redirect but never creates the www record, so the merchant is told to add a DNS record on a domain whose DNS they don't manage. Create it (or don't turn the redirect on). Screen: Domains.
- [x] (done by backend; the renew dialog quotes «جدّد بـ {price} لحد {date}» for 1–10 years and confirms that price) **Renewal price quote:** renewing a bought domain has no price quote endpoint, so the renew dialog cannot show the amount before confirming. Add a quote (like the purchase's). Screen: Domains → Bought domains → Renew.
- [x] (done by backend; a funnel/website email saved in «نص بسيط» sends blocks: null and its row says so) **Funnel/website email override in simple text:** when the store's email is built with blocks (174) and a funnel or website saves its own version as plain text, the server merges the store's blocks back in (an empty block list falls through), so the plain override never shows. An override with `blocks: null` should mean "plain body". Screen: Funnel → Emails, Website → Emails (175).
- [x] (done by backend: `configured` is true for a places-only store; the storefront line follows it, handoff 199 agent) The shipping quote's `configured` reads **false** for a store priced only by its own place list (handoff 164): `shippingQuoteService.pricesShipping` looks at governorate rates, the default rate, the free threshold and zones, not at `store_places.shipping_amount`. Why: before a place is picked the storefront says «بيتأكد وقت مكالمة التأكيد» instead of «بيتحسب بعد ما تختار منطقتك», and a store that sets prices only on cities/areas never shows "pick your area". The storefront treats a `store_place_rate` answer as priced meanwhile (lib/shippingLine.ts). Screen: storefront checkout, product quick form, cart.
- [x] (done by backend: place names match "<ar> (<en>)", either half, or the geoCode) The cart's «اشحن لـ» quote sends the governorate as "القاهرة (Cairo)" with no place id; the name matching in `placePricing.placesOf` compares it with the region's plain name, so a **region** price never applies to the cart estimate (the checkout sends `placeId`, so orders are right). Ask: also match the storefront's "<ar> (<en>)" spelling (or the region's `geoCode`). Screen: cart drawer / cart page shipping line.
- [x] (done by backend: preflight allows X-Shopper-Token and X-Store-Gate) **CORS: allow the `X-Shopper-Token` header** on the store API. `src/core/middleware/cors.js` `allowedHeaders` lists X-Cart-Token, X-Visitor-Id, X-Student-Token… but not `X-Shopper-Token` (handoff 185/186), so a browser on a store domain fails the preflight for every signed-in shopper call (account, orders, addresses, reorder, returns by `orderId`). Why: shopper accounts and "return from my account" can't work from the real storefront. Screens: storefront account pages, returns from the account order page.
- [x] (done by backend: available, openPath /apps/dropshipping) **App store: Shopify and WooCommerce "send orders" apps available** with `openPath: /apps/dropshipping` (handoff 181). Today they are still "coming soon" with no open path, so in production a merchant can't reach the dropship page's «متجرك التاني» section from the app store. Screen: Apps (app store) → Dropshipping.
- [x] (done by backend; the dialog opens the draft by productIds[0] and shows the page currency and review count) **Product link import report (180):** add `productIds`, the page's `sourceCurrency` and the number of imported reviews to the import report (GET `/catalog/imports/:id`). Why: the dashboard now finds the new draft by its `import:<source>` tag and creation time, reads the currency back out of the description, and counts pending imported reviews itself. Screen: Products → Import → «من رابط منتج».
- [x] (done by backend: LINK_INVALID / LINK_NOT_HTTPS / LINK_HAS_CREDENTIALS / LINK_NOT_PRODUCT / LINK_NO_PRODUCT_DATA; mapped) **Own error codes for link refusals (180):** "not https", "not a product link" and "the page does not publish product data" all come as one code with English detail text, so the dashboard tells them apart by matching that text. Give each its own code. Screen: Products → Import → «من رابط منتج».
- [x] (done by backend: any variant buyable) **Wishlist `available` for a product saved as a whole (188):** today it reflects the product's first variant only, so a shirt whose size M is sold out but L is in stock shows «مش متاح» in the wishlist.
