# What the redesign still needs from the backend

The redesign (docs/ux/REDESIGN_PROMPT.md) never shows a number the API does
not give. Each line here is one field the frontend needs, the screen that is
waiting for it, and what the screen does until it exists. Read from source on
2026-10-08; nothing here is a bug report.

## Sweep (Phase 10)
- GET /purchasing/purchase-orders: counts per status and a total, so the status chips can show figures once a store reaches the 200-row cap (exact only below it today).
- GET /stock-lots: counts per status (active / expiring / expired / empty), so the lots chips can carry figures; none are shown today.
- GET /stock-locations/transfers: product names (or productName / optionValues) on each line. Names are currently resolved from the default location's stock list, which is capped at 500 variants, so older or extra variants read «منتج محذوف».
- Automations run log: no per-status counts (done / skipped / failed), so the result filter shows no figures.
- Tracking pixel server event log: no per-status counts (accepted / failed), so its chips show no figures.
- Ad spend: no reach or cost estimate and no previous-period comparison in /profit/campaigns, so the four KPI tiles carry no change chip.
- Ad spend entries: no restore endpoint (delete is final; re-adding loses `source` and `adIds`), so delete asks instead of offering Undo.
- Reviews: a store reply to a review. There is no reply field on Review and PATCH /reviews/:id takes only {action: approve/reject}, so no reply sheet was built.
- Reviews: a way back to pending (PATCH accepts only approve / reject), so Undo after moderating a waiting review cannot return it to the queue.
- Reviews: a bulk moderate endpoint, so no BulkBar (approving 50 imported reviews is 50 taps).
- Questions: GET /product-questions has no `q` search and returns only the pending count, so there is no search and the published / hidden / all chips have no counts.
- Blog: GET /blog/posts returns no per-state counts, so the draft / published / scheduled chips have none.
- GET /workspaces/:ws/quotes should return a count per status (quoted, accepted, declined, cancelled, expired), not only newCount, so every chip can show its number.
- GET /workspaces/:ws/quotes rows carry no totalAmount/currency, so the list cannot show the quote's value on the row.
- GET /workspaces/:ws/courses/:id does not document studentsCount on the detail; the Students chip shows a count only if it is present.
- PATCH /workspaces/:ws/courses/:id: confirm the answer includes modules. The page keeps the outline it has when it does not.
- GET /workspaces/:ws/subscriptions is capped at limit 200 with no cursor; a store with more gets no pagination.
- The file library gives no download/preview URL for the merchant, so a file row can only be deleted.
- GET /settlements has no text or carrierCode filter, so the settlements list has no search and no courier filter (only status, limit and before).
- GET /profit/pnl returns no previous-period figures, so the profit stat cards carry a hint instead of a change chip.
- GET /store-reports/sales-by-option and /sales-by-collection return no store totals, so those two reports have no stat strip.
- Inbox: no way to read one conversation by id. A ?conversation= link to a conversation outside the first 30 open ones is looked for once in the first 30 closed ones and then dropped.
- Inbox: counts (open, mine, unread) cover open conversations only, so the chips show no figures on the closed list.
- Inbox: conversation rows do not say who sent the last message or its delivery status, so the list cannot show 'You: …' or ticks.
